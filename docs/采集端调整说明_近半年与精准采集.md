# 采集端调整说明:只采近半年 · 精准采集(接口 v1.3)

> 面向采集端。工作台已升级到接口 **1.3**(`GET /api/ping` 的 `api_version` 为 `"1.3"`)。完整接口见《采集端接口.md》,本文只说明这次需要采集端配合调整的地方。

## 1. 为什么要改

现有数据里,笔记发布时间跨度 2022–2026 年,旧笔记的玩法、热点、价格已经过时,拿来拆解爆款会误导复刻。另外搜索出的笔记里有一部分只是正文里顺带提了一句关键词,和主题无关。所以:

1. **只采近半年(180 天)内发布的笔记。**
2. 搜索结果多看一些、筛选后再回传,保证回传的都是相关、较新的笔记。

## 2. 任务里新增的字段

`GET /api/tasks` 返回的每条任务多了三个字段:

```json
{ "id": 12, "type": "keyword", "query": "腐乳做法", "limit": 20,
  "max_age_days": 180, "note_type": "image", "sort": "popularity" }
```

| 字段 | 含义 | 采集端要做的 |
|---|---|---|
| `max_age_days` | 只要最近 N 天内**发布**的笔记;`0` = 不限 | 见第 3 节 |
| `note_type` | `image` 只要图文;`all` 不限 | `image` 时跳过视频笔记 |
| `sort` | `popularity` 最热 / `general` 综合 / `latest` 最新 | 按对应排序搜索 |

- 字段缺失时按默认值处理:`max_age_days=180`、`note_type=image`、`sort=popularity`。
- **博主任务(`type: "author"`)不受时间限制**,仍然按原规则采集。

## 3. 发布时间怎么处理(重点)

1. **每条笔记都要带 `published_at`**(格式 `YYYY-MM-DD`,也兼容 `YYYY-MM-DD HH:MM`)。
2. 必须是**真实发布日期**,不要用「编辑于」「更新于」的时间(编辑时间会让旧笔记看起来很新)。详情页里同时有两个时间时,以「发布」为准。
3. 小红书详情页常显示相对时间(「3天前」「昨天」「5月12日」)——请采集端换算成具体日期再回传:
   - 「N 分钟前 / N 小时前 / 昨天 / N 天前」→ 按采集当天换算;
   - 「MM-DD」且没有年份 → 取最近的、不晚于今天的那个日期;
   - 带年份的(「2024-03-05」)原样使用。
4. 判断规则:`今天 − published_at > max_age_days` 的笔记**不要回传**,继续往下翻找足够的新笔记。
5. 实在拿不到发布时间:允许不传(留空),工作台会保留,但不要用采集日期顶替。

## 4. 采多筛少

近半年 + 图文 + 相关,符合条件的会比以前少,按下面的方式找够 `limit` 条:

- 搜索结果**最多往下翻 5 屏(或扫描最多 `limit × 5` 条)**,边翻边筛,够 `limit` 条就停。
- 翻完仍不够:有多少回传多少,正常返回 `done`,不要因为不够而标失败。
- 筛选顺序:先看发布时间 → 再看是否图文 → 再看标题/正文是否真的和 `query` 相关(只在正文里顺带提到的,排到最后)。

## 5. 一个任务一个词

工作台已经保证一个任务只有一个关键词。采集端请**原样搜索 `query`**,不要拆词、不要自行加词、也不要把多个任务合并搜索。

## 6. 工作台的兜底

工作台收到笔记后也会再检查一遍:发布时间超出 `max_age_days` 的笔记会被丢弃,并在回传结果里用 `skipped_old` 告诉你数量:

```json
{ "ok": true, "results": [ { "task_id": 12, "saved": 14, "duplicated": 2, "new_in_library": 12, "skipped_old": 3, "status": "done" } ] }
```

- `skipped_old` 偏大说明采集端的时间过滤没生效,请检查第 3 节。
- 缺少 `published_at` 的笔记不会被丢弃(工作台里发布时间显示为空)。

## 7. 自检清单

- [ ] `GET /api/ping` 返回 `api_version: "1.3"`
- [ ] 领到的任务里能读到 `max_age_days`
- [ ] 回传的每条笔记都有真实的 `published_at`,没有「编辑于」时间
- [ ] 回传里没有早于 180 天的笔记,`skipped_old` 基本为 0
- [ ] `note_type=image` 时没有视频笔记
- [ ] 不够条数时照常返回 `done`
