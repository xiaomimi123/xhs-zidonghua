# 版本号与回滚

页面左下角(用户端和管理端)显示当前线上的版本,例如 `v1.58` 和下面的提交号、构建时间。点一下会复制,反馈问题、需要回滚时把它发给我。

## 版本号是什么

- `v1.N`:N 是 git 提交的总数,每个提交一个号,只增不减。`git log --oneline` 数到第 N 个就是这个版本的代码。
- 版本号后面有 `+`:构建时还有没提交的改动。这种版本没法精确回到源码,所以**部署前先提交**。
- 版本信息在构建时由 `tools/release.py` 写入 `app/version.json`(不进 git),随镜像一起发布;没有这个文件(本地开发)显示 `dev`。

## 发布

```bash
git commit ...                       # 先提交,版本号才对得上代码
python tools/release.py build        # 写入版本号 → 构建镜像 → 给镜像打上版本标签(如 xhs-workbench:v1.58)
docker compose up -d                 # 部署
```

每次 `build` 会保留最近 12 个版本的镜像,更旧的自动清掉。

## 回滚

```bash
python tools/release.py list              # 看有哪些版本可以退
python tools/release.py rollback v1.57    # 备份数据库 → 换回 v1.57 的镜像 → 重启
```

回滚前会先在容器里备份一份数据库(`data/backup-时间-before-rollback.db`)。

注意:
- 数据库只会往前升级。旧版本代码能读新版本的库,新版本新增的列它会忽略,一般没问题;
  如果新版本改过表结构而旧版本不认识,要连数据一起退回,用 `data/backup-*.db`(每次部署前都会备份一份)。
- 回滚只退代码和页面,`data/` 里的图片、成品、数据库不动。
- 某个版本的镜像已被清掉(超过保留数量)时,用 `git checkout <那个提交>` 后重新 `build` 也能得到同样的版本。
