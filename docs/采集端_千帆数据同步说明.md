# 采集端:千帆后台数据同步说明(协议 v1.5 新增)

工作台要在「数据看板」里展示小红书千帆后台的数据。**读页面的活由采集端干**(用已登录千帆后台的浏览器),工作台只负责下发任务、接收数据、展示。

## 一、新增的任务类型 `qianfan`

和原来的 `keyword / title / author` 同一个接口领取,**必须在 `types` 里声明才会领到**(没声明的旧采集端领不到,不会受影响):

```
GET /api/tasks?worker=xxx&types=keyword,title,qianfan
```

领到的千帆任务长这样:

```json
{"id": 123, "type": "qianfan", "query": "hot_topics", "limit": 0,
 "params": {"period": "7d", "category": "美食"}}
```

| query | 含义 | params |
|---|---|---|
| `account` | 账号数据(粉丝、曝光、互动等,取账号概览页最新一天/近 7 天) | 无 |
| `notes` | 我们发布的笔记表现(笔记管理 / 数据中心里的笔记列表) | 无 |
| `hot_notes` | 热门笔记榜 | `period`:`1d/7d/30d`;`category`:品类名,空 = 全站 |
| `hot_topics` | 热门话题榜 | 同上 |
| `hot_keywords` | 热门关键词(搜索词)榜 | 同上 |

领取顺序:用户任务 → 千帆同步 → 笔记库沉淀任务。千帆任务领走后同样靠心跳续租(15 分钟没动静会退回重派),抓完一个任务应在几分钟内回传。

## 二、回传 `POST /api/qianfan/ingest`

鉴权同其他接口(`Authorization: Bearer <采集端 Token>`)。每个任务回传一次,`task_id` 填领到的任务 id,工作台据此把任务标成完成。

**账号数据**(`kind=account`):

```json
{"task_id": 123, "kind": "account",
 "account": {"name": "账号名", "fans": 12345, "new_fans": 35, "notes": 48,
             "views": 20310, "likes": 612, "collects": 480, "comments": 51, "shares": 20, "visits": 330}}
```

**笔记表现**(`kind=notes`):

```json
{"task_id": 124, "kind": "notes",
 "items": [{"note_id": "xxx", "title": "笔记标题", "published_at": "2026-11-01",
            "views": 3200, "likes": 120, "collects": 80, "comments": 9, "shares": 4, "new_fans": 6}]}
```

**热门笔记榜**(`kind=hot_notes`):

```json
{"task_id": 125, "kind": "hot_notes", "period": "7d", "category": "美食",
 "items": [{"rank": 1, "title": "笔记标题", "author": "博主", "likes": 52000, "collects": 31000, "comments": 2100, "heat": 98000}]}
```

**热门话题 / 关键词榜**(`kind=hot_topics` / `hot_keywords`):

```json
{"task_id": 126, "kind": "hot_topics", "period": "7d", "category": "美食",
 "items": [{"rank": 1, "name": "早餐打卡", "heat": 98000, "notes": 4200}]}
```

话题榜用 `name`(或 `topic`),关键词榜用 `keyword`(或 `name`)。

**抓取失败**:不要不回,回一个 error,工作台会记原因并在一小时后重试:

```json
{"task_id": 123, "kind": "account", "error": "千帆登录已过期,需要重新登录"}
```

返回:`{"ok": true, "stored": 条数}`。`400` 表示数据不合格(`kind` 不对、`items` 为空、没有标题 / 名称),`detail` 里写了原因。

## 三、字段说明与约定

- 数字可以传 `12345`,也可以传页面上看到的 `"1.2万"`、`"3.4w"`、`"5千"`,工作台自己转。
- **页面上没有的字段就不传**,不要填 0 或编造——看板会把缺失的显示成空白。
- 字段名中文表头也认(如 `粉丝数`、`曝光量`、`标题`、`热度`),但建议用上面的英文名。
- `items` 一次最多 300 条,够用就行(榜单取前 50 即可);`rank` 不传则按顺序编号。
- `period` / `category` 必须原样回传下发时的值,工作台按「品类 + 周期」分开存。
- 笔记表现里的 `title` 要是**页面上显示的完整标题**:工作台靠标题把它和自己生成的稿子对上号。
- 千帆后台的页面结构、接口都可能改版。**优先读页面加载时的 XHR 数据(JSON)而不是解析 DOM**;改版导致取不到数据时回 error 并写清楚缺了什么,不要回空数据。

## 四、自测

没接上之前,管理端「数据看板 → 同步设置 → 手动导入」可以直接粘上面的 JSON,用来核对字段;「载入示例数据」可以先看页面效果。接口也可以直接用 curl 试:

```bash
curl -X POST http://<工作台地址>:18765/api/qianfan/ingest \
  -H "Authorization: Bearer <Token>" -H "Content-Type: application/json" \
  -d '{"kind":"hot_topics","period":"7d","items":[{"rank":1,"name":"早餐打卡","heat":98000}]}'
```

(不带 `task_id` 也能回传,只是不会关联任何同步任务。)

## 五、不要做的事

- 不要抓取任何账号以外的人的私密数据,只读自己账号的千帆后台。
- 控制频率:同一类数据 12 小时内最多一次(工作台的默认间隔),不要自己加循环刷新。
- 千帆页面出现验证码、风控提示时立即停止,回 error(如「出现验证码,需要人工处理」),不要尝试绕过。


## 四、多账号(店铺下有多个账号时)

**账号数据一次回传所有账号**,每个账号各存一份快照、各有粉丝趋势。`account_id` 用账号的 user_id,`name` 是昵称:

```json
{"task_id": 123, "kind": "account",
 "accounts": [
   {"account_id": "6a8eaa12000000001e00aaaa", "name": "示例账号A", "red_id": "10000001", "fans": 1015, "views": 254, "likes": 3, "collects": 1, "comments": 2, "shares": 7},
   {"account_id": "6a8eaa12000000001e00bbbb", "name": "示例账号B", "fans": 49}
 ]}
```

- 只有一个账号时,仍然可以用原来的 `account` 单对象写法(`account_id` 可选)。
- 以前没带 `account_id` 存下的快照,会按昵称认领给第一次带 ID 回传的同名账号,趋势不断档。
- 数字字段规则同上:页面上没有的不传。

**笔记表现里每篇笔记带上所属账号**(`account_id`、`account_name`),工作台据此按账号筛选,并在稿子「指定了发布账号」时只在同一个账号里按标题对号,避免串号:

```json
{"task_id": 124, "kind": "notes",
 "items": [{"note_id": "xxx", "title": "笔记标题", "views": 3200, "likes": 120,
            "account_id": "6a8eaa12000000001e00bbbb", "account_name": "示例账号B"}]}
```

`notes` 一次最多收 1000 条。


## 五、多店铺(同一个千帆账号下有多个店铺时)

同一个千帆账号同一时间只能登录一个店铺(登录第二个会把第一个挤掉),所以采集端只服务**当前登录的那个店铺**,换店铺登录后自动换着服务,另一个店铺的同步任务会排队等着。

- 领任务时带上自己的店铺:`GET /api/tasks?types=qianfan&worker=xxx&shop=<店铺ID>&shop_name=<店铺名>&kinds=account,notes,hot_notes,hot_keywords,hot_topics`。店铺 ID 取 `GET /api/edith/seller/info/v2` 返回的 `seller_id`。`kinds` 是这个采集端能做的类别,不传 = 都能做。
- 只会领到这个店铺的任务,和不分店铺的任务(平台话题榜 `hot_topics`)。**不传 `shop` 领不到分店铺的任务。**
- 任务的 `params.shop` 是店铺 ID;回传时 `shop_id`、`shop_name` 原样带上,工作台按店铺分开存。
- 每轮领任务前重新确认当前登录的店铺;任务的店铺和当前登录的不一致就不要做,回一个 error。
- 店铺第一次出现时自动登记。工作台按「最近 150 秒内来领过任务」判断店铺是否在线,看板上会提示哪个店铺很久没同步。
