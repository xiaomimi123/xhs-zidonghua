# 小红书流水线工作台

选赛道 → 采集端抓爆款 → DeepSeek 拆解套路 → 批量复刻同风格原创笔记(含配图) → 打包导出 → 手动发布

## 启动(Docker,推荐)
```bash
docker compose up -d --build
```

| 入口 | 地址 | 谁用 |
|---|---|---|
| 用户端 | http://127.0.0.1:18765 | 运营:选赛道、看采集结果、拆解、复刻、导出 |
| 管理端 | http://127.0.0.1:18765/admin | 管理员:接口配置、采集监控、笔记库、赛道配置、账号安全 |
| 采集端接口 | `/api/tasks`、`/api/notes` | 你的采集程序,见 [docs/采集端接口.md](docs/采集端接口.md) |
| 采集端调整(v1.3) | 只采近半年、一词一任务 | [docs/采集端调整说明_近半年与精准采集.md](docs/采集端调整说明_近半年与精准采集.md) |

- 首次启动会生成管理员密码,写在 `data/初始管理员密码.txt`;登录管理端后请立即修改(修改后该文件自动删除)
- 所有数据在 `./data`(挂载进容器的 `/app/data`),删除或重建容器不会丢数据
- 端口、管理员密码、pip 镜像源可在 `.env` 里改,参考 `.env.example`

常用命令:

| 操作 | 命令 |
|---|---|
| 查看日志 | `docker compose logs -f` |
| 停止 | `docker compose down` |
| 更新代码后重新部署 | `docker compose up -d --build` |
| 备份 | 停止后打包整个 `data/` 目录 |

不用 Docker 时也可以双击 `run.bat`(两者都占用 18765 端口,不要同时运行)。

## 部署到服务器
1. 把项目目录上传到服务器(不需要 `.venv`;要迁移现有数据就连 `data/` 一起传)
2. 国内服务器拉包慢:`cp .env.example .env`,取消 `PIP_INDEX_URL` 那行的注释
3. `docker compose up -d --build`
4. 管理端「账号安全」里设置**用户端访问密码**,否则任何人都能使用并消耗接口额度
5. 前面加 HTTPS 反向代理,并只对外开放 443。Nginx 示例:
   ```nginx
   server {
       listen 443 ssl;
       server_name your.domain.com;
       # ssl_certificate / ssl_certificate_key ...
       client_max_body_size 25m;   # 管理端导入笔记文件
       location / {
           proxy_pass http://127.0.0.1:18765;
           proxy_set_header Host $host;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```
   用了反向代理时,把 `docker-compose.yml` 的端口改成 `"127.0.0.1:18765:18765"`,只允许本机代理访问
6. 采集端 Token 在管理端「接口配置 → 采集端对接」查看,泄露后可一键重新生成

## 采集任务的三种类型
用户端「采集」页可以追加任务:**按关键词**(搜索爆款)、**按标题**(粘贴一篇爆款标题找同类)、**按博主**(填主页链接或小红书号,采集 TA 的代表作来拆解写法)。

- 博主任务只会发给声明支持它的采集端:采集端领任务时要带 `types=keyword,title,author`,不带就只领到关键词和标题任务,所以旧采集端不会领到处理不了的任务
- 博主笔记在笔记库里的关键词记为「博主:昵称」,可以按它筛选;视频笔记有「视频」标记,不参与爆款统计
- 协议细节见 [docs/采集端接口.md](docs/采集端接口.md) 第 5.1 节

## 管理端
- **概览**:采集端在线状态、任务/笔记/草稿统计、上线检查清单
- **采集监控**:各采集端心跳,全部采集任务的状态、失败原因、重新下发
- **笔记库**:全局帖子库(同一篇只存一份,多个项目共用,删项目不删帖子)。每篇自动记录赛道/关键词/采集端,AI 打内容类型、目标人群、爆点标签,并按互动量分为爆款/热门/普通;支持多维筛选、手动修正分类、重新打标签、批量导入 .json / .xlsx / .csv
- **导出备份**:「笔记库 → 导出备份」把笔记(完整数据、采集端原始字段、AI 标签)、Excel 表格和图片打成压缩包,保存在 `data/archive/`,以后可以直接重新导入。除此之外,整个 `data/` 目录就是全部数据,定期复制一份即可
- **赛道配置**:用户端可选的赛道、推荐关键词、排序与启用;每个赛道一份知识库 + 一份通用规则,拆解和复刻时按项目赛道只带对应那份
- **合规词库**:广告法极限词、站外导流、收益/疗效承诺(高风险)和 AI 腔、营销黑话、功效宣称如「抗炎」(低风险,只提示不拦截、不自动改),支持排除短语、试扫;被限流后把真实命中的词补进来并写明日期
- **接口配置**:DeepSeek、生图模型、复刻并发、每任务采集条数、采集端 Token
- **账号安全**:管理员密码、用户端访问密码

## 拆解与复刻的质量保障
- **按数据拆解**:拆解前统计「本次参考 / 赛道爆款 / 赛道普通」三组的标题字数、含数字比例、正文字数、段落、emoji、分点、结尾互动等指标;拆解卡每个字段标注依据(数据 / 归纳 / 知识库),样本不足 5 篇时不做对比结论
- **不编造**:复刻时亲身经历、使用时长、价格、实测结果一律写成【补充:…】占位符;另有规则兜底,把「我实测了…」「用了3个月」这类第一人称说法标为「需确认」
- **自动审稿**:成稿后对照拆解卡审稿。代码算量化贴合度(标题/正文字数、段落、emoji、分点、互动、话题 vs 参考均值),DeepSeek 给标题、开头钩子、结构、干货密度、语气人设、互动引导六个维度打分,并列出「原文→改为→原因」的问题清单和一份修改版;总分 = 维度均分×75% + 量化贴合×25% − 合规扣分,对应 S/A/B/C/D。修改版需要作者点「采用修改版」才替换;可选模拟评论区(接口配置里开启)
- **配图**:提示词必须点名画面主体,图上要显示的文字必须写在「」里(只有这些字会出现在图上,并过合规词库);生成时自动加「主题」并禁止多余文字。瞬时网络错误自动重试,图片按位置对应提示词,失败的只补缺失的那几张,不会重复扣费;「全部重画」才会整套重新生成
- **主题分类**:每篇笔记有两个容易混淆的字段——「搜索词」是采集时用的词(来源,可能采到不相关的内容),「主题」是 AI 按笔记内容判断的真实主题(如姜黄粉、生姜粉、咖啡店探店)。笔记库和用户端采集页都能按主题筛选;拆解时选了多个主题会提醒。「笔记库 → 整理主题」可以手动合并/改名,也可以点「AI 建议合并」让 AI 给方案,确认后再应用
- **选题守则**:关键词是并列的搜索词,不是要组合的主题。拆解时会列出笔记里实际涉及的「可写主题」(可在拆解卡里删改),每篇复刻只写其中一个;代码会检查有没有把参考笔记里没有的关键词组合写在一起(拆解卡名称、复刻稿),发现就带着反馈重写一次,仍不行就在草稿上标「选题冲突」;审稿多一个「合理性」维度。项目的关键词和内容方向可以在「采集」页「本项目 → 编辑」里随时修改
- **封面**:第 1 张默认带大字标题(模型没写时由代码补上)
- **合规扫描**:成稿后用词库逐条扫描标题、正文、话题;命中高风险词时自动让 DeepSeek 按扫描结果改一次(可在接口配置关闭),作者也可以随时点「按建议修改」;保存时重新扫描;导出前提醒未处理的稿子

## 回归测试
改提示词、合规词库或评分规则之后跑一遍,和基线对比,防止效果变差:

```bash
docker compose exec workbench python -m evals.run --offline          # 规则类,不调 API,几秒
docker compose exec workbench python -m evals.run --live --repeat 3  # 调 DeepSeek 跑拆解→复刻→审稿,和基线对比
docker compose exec workbench python -m evals.run --live --repeat 3 --save-baseline   # 确认结果满意后设为新基线
docker compose exec workbench python -m evals.run --snapshot 美妆护肤 --name beauty_real   # 从笔记库导出真实样本集
```

- 样本集在 `evals/fixtures/`,目前只有合成样本 `beauty_synthetic.json`;真实数据接入后用 `--snapshot` 生成真实样本集,删掉合成样本,再重新保存基线
- 每次结果(含生成的拆解卡、稿子、审稿)保存在 `evals/results/`,基线在 `evals/baseline.json`;某项通过率比基线下降 20% 以上判为退化

## 说明
- 生图接口默认按 OpenAI 兼容 `/images/generations` 调用,接入其他第三方模型时只改 `app/imagegen.py`
- 拆解、复刻、打标签在服务端后台运行,任务状态存在数据库里,关掉网页或重启服务都会接着跑;服务只能单进程运行(不要开多个 worker 或多个容器副本)
- 代码结构:`app/api_user.py` 用户端接口 · `app/api_admin.py` 管理端接口 · `app/api_collector.py` 采集端接口 · `app/auth.py` 鉴权
- 数据都在 `data/`(SQLite、图片、导出包、签名密钥 `secret.key`);升级前的数据库备份在 `data/workbench.v1.bak.db`

### 开发者备忘

- **改数据库结构**:在 `app/db.py` 的 `MIGRATIONS` 末尾加一项 `(版本号, 名称, 函数)`,函数里用 `add_column(c, 表, 字段, 类型)` 等幂等写法。启动时按 `schema_version` 表依次执行没跑过的,执行前自动备份成 `data/workbench.pre-migrate-v版本号.bak.db`;库的版本比程序新时会拒绝启动。每次启动都要做的事(补种子数据、把中断任务退回待办)放在 `_startup_fixups`,不要放进迁移。
- **测试用例位置**:`evals/cases/offline_*.py` 不依赖数据库;`evals/cases/iso_*.py` 在临时数据库里按顺序执行,前面用例造出来的数据通过 `env` 传给后面的(所以顺序不能随便换)。新增用例尽量写成不依赖前面数据的独立用例。

- **爆款回流(核心闭环)**:批量复刻 → 发布测试 → 千帆数据回流 → 判定爆款 → 以爆款为样本继续复刻。逻辑在 `app/loop.py`:`evaluate()` 按标题把稿子对上千帆笔记并判定(爆款 = 发布满 N 天、互动 ≥ 下限、≥ 账号平均的 X 倍,阈值在管理端「接口配置 → 爆款回流」),`spawn()` 把爆款稿登记进笔记库当样本、新建任务从「拆解」阶段接入原流水线(任务记录来源稿和代数),`auto_tick()` 在打开「自动继续复刻」后自动复刻新爆款(每天有上限、最多连续 3 代、默认关)。员工端「复盘」页展示漏斗、爆款榜、哪类更容易爆、继续复刻是否更有效。
